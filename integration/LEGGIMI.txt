TREC: PROGETTO ORIGINALE CON INTEGRAZIONE AGGIUNTIVA

I 44 file originali non sono stati modificati. Tutto il nuovo codice è in integration/.
Credo verifica la prova della credenziale; oidc-provider rilascia i JWT al client.

1. ESTRAZIONE

Salva trec-oidc-provider-integrato.zip sul Desktop D:\Desktop.
Apri lo stesso terminale WSL e lo stesso utente ricca con cui il login funzionava.
Ferma prima i vecchi processi provider, Holder, Issuer e client con Ctrl+C.
Non eliminare il vecchio progetto e non eliminare ~/.afj.

Esegui, una riga alla volta:

cd ~/Tirocinio
unzip /mnt/d/Desktop/trec-oidc-provider-integrato.zip
cd ~/Tirocinio/trec-oidc-provider-integrato
nvm use 18
cd integration
npm ci
cd ..

Se unzip segnala che la cartella esiste già, non sovrascrivere una copia già configurata:
scegli prima una nuova directory di estrazione.

Non eseguire npm install nella radice e non eseguire tsc sui file originali.
Le dipendenze aggiuntive sono installate soltanto in integration/node_modules.
Se npm ci richiede gli strumenti di compilazione nativa, su Ubuntu/WSL installali:

sudo apt-get update
sudo apt-get install -y build-essential python3

Poi ripeti npm ci dalla cartella integration. Non usare --ignore-scripts:
gli script di installazione servono per le librerie native degli agenti.

2. IMPORTAZIONE DELLA CONFIGURAZIONE ESISTENTE

Dalla radice della nuova cartella esegui:

node integration/configure.cjs "$HOME/Tirocinio/trec-oidc-provider"
node integration/verify-originals.cjs

Risultato della seconda riga: ORIGINAL_FILES_UNCHANGED=44

Il primo comando legge i tre .env del vecchio progetto e crea i file privati
integration/config/provider.env, holder.env e issuer.env.
Non stampa segreti, non modifica i vecchi file e non crea DID o altre risorse.
Mantiene ID e chiavi dei wallet Askar e configura le porte locali:
provider 3000, Verifier 3001, Holder 3002, Issuer 3003, client 3004.
Genera nuove chiavi e un nuovo segreto per questa coppia provider/client locale.

Se dice "Configurazione gia presente", non ripetere l'importazione: usa i file già
generati. Per controllarli localmente puoi aprirli con nano, senza incollarli in chat.
Se il vecchio progetto si trova altrove, sostituisci soltanto il percorso sorgente.

3. TEST AUTOMATICI

cd integration
npm test
cd ..

Sono previsti 13 test. I test OIDC usano account di prova e quelli Credo simulano
gli eventi: non usano il tuo wallet e non scrivono sulla blockchain.

4. AVVIO: TRE TERMINALI WSL

TERMINALE 1 - Provider e Verifier insieme:

cd ~/Tirocinio/trec-oidc-provider-integrato
nvm use 18
node integration/run.cjs provider

TERMINALE 2 - Holder con la credenziale già ricevuta:

cd ~/Tirocinio/trec-oidc-provider-integrato
nvm use 18
node integration/run.cjs holder

TERMINALE 3 - Client locale:

cd ~/Tirocinio/trec-oidc-provider-integrato
nvm use 18
node integration/run.cjs client

Apri nel browser:

http://localhost:3004

Premi "Accedi con la credenziale". Copia l'intero invito mostrato dalla pagina
del provider e incollalo nel terminale Holder. Attendi la pagina di consenso,
quindi premi "Conferma".

Esito atteso nel provider:
OIDC_PROOF_VERIFIED=true

Esito atteso nel client:
OIDC_ACCESS_TOKEN_VERIFIED=true
OIDC_LOGIN_VERIFIED=true

I token vengono ricevuti e verificati dal client senza essere mostrati nel browser
o nei log. Per ripetere il test, riavvia soltanto l'Holder e riparti dalla home
del client. Non riutilizzare una vecchia pagina callback o un vecchio invito.

Per questi test non avviare anche verification/test-proof.ts: il Verifier viene
già avviato dal provider.

5. ISSUER: SOLO SE VUOI EMETTERE UN'ALTRA CREDENZIALE DIMOSTRATIVA

Non è necessario se il tuo Holder conserva già la credenziale funzionante.
Il comando aggiunto riutilizza la Credential Definition esistente e gli attributi
dimostrativi dell'Issuer originale. Non registra DID, schema o Credential Definition.

cd ~/Tirocinio/trec-oidc-provider-integrato
nvm use 18
node integration/run.cjs issuer

Avvia l'Holder in un altro terminale e incolla l'invito dell'Issuer.
Occorre il wallet originale dell'Issuer, che contiene la parte privata della
Credential Definition: conoscere soltanto l'ID pubblico non basta per emettere.

6. SE QUALCOSA NON PARTE

"Wallet esistente non trovato": verifica di essere nello stesso utente WSL e
di aver importato gli ID corretti. Il programma si ferma invece di creare un
wallet vuoto. Non cambiare le chiavi dei wallet.

"File originale modificato": confronta il file indicato con lo ZIP consegnato.
Non cancellare il controllo hash. Un file originale modificato non soddisfa più
il vincolo di questa integrazione.

"INVALID_STATE" o callback non valida: riparti da http://localhost:3004 e usa
un nuovo login; il codice di autorizzazione si usa una sola volta.

I file integration/config/*.env e integration/.oidc-data sono privati e non
sono inclusi nello ZIP. Mantienili insieme se fai un backup del nuovo ambiente.

Verifiche eseguite: test HTTP/JWT e persistenza superati su Node 18.20.8.
Da ripetere nel tuo WSL: il login completo con i tuoi wallet e cheqd Testnet.
Il collaudo degli agenti nativi non è stato possibile nel Windows di preparazione.
